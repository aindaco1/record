## Installed update and capture

Preserved an explicit 1.4.0 rollback bundle. Launching installed 1.4.0 displayed
the automatic 1.4.1 update prompt. The normal Sparkle install flow replaced and
relaunched the app; **Check for Updates…** then reported 1.4.1 as current.
The installed version is 1.4.1, build 18. Its executable matches the public ZIP:
`0a185d4a8a09c3de95164f40ddb290ecb183a15406b63fbad93aa0c5e04477ab`.
Installed signature, entitlements, TCC identity, staple, and Gatekeeper checks
passed. Capture used the existing grants without another permission request.

The final smoke run targeted the installed public app and a local synthetic
source on a 1280 × 720 point Retina virtual display:

| Case | Observed result |
|---|---|
| Stop during Resume | Normal SIGINT delivered only after the exact resuming state was observed; conflicting commands disabled; finalized 2560 × 1440 MOV and independent WAVs, about 3.5 seconds |
| Secondary-display region | A 400 × 300 point selection produced an 800 × 600 MOV and independent WAVs, about 3.5 seconds |
| Selected application exit | Returned to idle with `sourceUnavailable`; preserved three fully decodable raw video/system/microphone segments, about 3.5 seconds |

Every inspected file decoded completely without errors. Final WAVs were
48-kHz stereo 24-bit PCM; MOV files contained only HEVC video. Test media and
private metadata remain local. Temporary helpers use semantic menu actions so
changing status rows cannot redirect an action to a different command.
