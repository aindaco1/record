Updated: 2026-10-04. Status: release authorized; publication and installed-update verification pending.
Environment: Apple Silicon, macOS 27.0 (26A428), Xcode 27.0 (27A266a).

## Agreed scope

All six high-priority items in the [Handy review](../project/handy-review-2026-10-02.md).
The candidate also includes engine-aware speech language, English/Spanish UI and
accessibility improvements, global automatic vocabulary, and multiple audio-file
import with a file-transcription CLI. The October 4 expansion adds Quick Dictation
and local recording controls through CLI and Apple Shortcuts to the same pipeline.
The user selected safe stop and preservation on selected-microphone disconnect,
Recent Sessions limited to the current destination plus private recovery storage,
and an automatically shown compact panel with an off setting. Available hardware
is built-in audio only. Keep USB/Bluetooth and external-display evidence separate.

## Language, vocabulary and import revision

The signed `1.5.0-local` app imported two selected synthetic AIFF files in one
native selection, one English and one Spanish. Real local Parakeet recognition
completed both, using speaker `source`. Both owned audio copies exactly matched
their original SHA-256 hashes. Each canonical transcript applied one global
`Dust Wave` correction; raw recognition and the pre-vocabulary transcript
remained separately available. This is short synthetic speech evidence, not a
general recognition-quality claim.

Native review confirmed all six Spanish Settings pages, persisted
vocabulary editing, and interface-language independence from Automatic speech
recognition. Layout fixes give engine/language controls sufficient width and
shorten the sidebar's Screenshots label. Deterministic layout checks include
Spanish labels at minimum width; the native review used the saved window size.
Stable recording/transcription announcements are tested independently from clock
and meter updates. A complete audible VoiceOver pass remains pending.

The signed CLI completed the same two-file English/Spanish batch after native
input and output dialogs, printed both session paths, and exited zero. Both
checkpoints were complete and both source copies matched their originals.
Plain inaccessible paths fail with actionable `--authorize` guidance. Native
review caught AppKit initialization/threading issues: the synchronous CLI entry
finishes application launch and resolves dialogs on the real main thread before
starting asynchronous processing. The GUI retains its synchronous AppKit loop.

Removing the temporary vocabulary rule and applying vocabulary again to an
existing synthetic session restored its pre-vocabulary spelling. Source audio,
raw transcript, and cleaned transcript hashes stayed unchanged, and the change
report became empty. Test vocabulary, destination, and interface-language
preferences were restored after the checks.

The standard development command passed deterministic validation and native
Apple cleanup for the pinned synthetic corpus. Hosted Jev did not complete
(22 controls unevaluated); it supplies no semantic pass. Its local evidence is
`.build/jev/2026-10-03T23-11-36-182Z-87377fa8/workflow.json`.

## Observed outcomes and limits

The signed development app uses the existing Developer ID identity and reviewed
entitlements. It is version `1.5.0-local`, not a notarized public release.
Test recordings, raw diagnostics and preferences remain local and are excluded
from this repository. The original save folder, System Default microphone,
both-source preference and Off recording shortcuts were restored after testing.

Audio-only samples included a 22.5-second microphone recording, a 30.13-second
system recording and a combined session with independent start offsets. WAV
sources were 48 kHz, 24-bit PCM (mono microphone, stereo system audio), passed
full decode checks, and had finalized manifests without capture-health events.
The system fixture was a generated tone; this is not speech-quality evidence.

Explicit audio-only microphone routing exposed a Voice Processing I/O failure.
The specific-input path now uses raw capture; System Default retains existing
voice processing. The same settled engine is reused after route changes.
[ADR 0026](../adr/0026-local-recording-workflow.md) records this behavior.
Native review also found and fixed stale idle meters and the app's transient
aggregate device appearing in the microphone list. Deterministic cases cover
these regressions, interleaved-channel metering and local-date filtering.

Transcription fixtures exercise one failed track, preserved successful output,
retry after reopening, defer during a late completion, and duplicate directory
aliases. Media bytes remain unchanged. Native transcript previews used an
explicit synthetic fixture; they do not establish recognizer accuracy. Clean and raw Copy transcript round trips were verified with the synthetic fixture
in TextEdit before the Settings revision.

The downloader probe used a disposable signed sandboxed host with the packaged
helper and the production network-denied main-app entitlements. It downloaded
only the existing pinned public model asset and did not replace the installed
model cache. Completion-handler URLSession downloads require byte-count KVO;
download-delegate callbacks are not delivered for that API, and overall task
progress units are not byte counts. The final probe checks actual received
bytes against the pinned size. Deterministic tests cover observation teardown
and cancelled installation preserving an existing model.

Native Apple evaluation evidence is under the ignored `.build/jev` directory:
baseline `2026-10-02T23-10-40-310Z-48615a65` and regressions
`2026-10-02T23-17-14-234Z-c57a9709`. These are native passes with incomplete Jev
requests, not hosted semantic passes. No private recording or transcript was
supplied to the evaluator.

The existing [hardware acceptance issue](https://github.com/aindaco1/record/issues/6)
remains open. USB/Bluetooth route changes, external displays, permission-revocation
and clean-account flows, call-length behavior, physical shortcuts, complete
keyboard/VoiceOver behavior and actual captured-frame panel exclusion are not
established by this candidate's automated results. Do not mark them passed or
not applicable merely because the needed hardware or interaction is unavailable.


## October 4 dictation and automation expansion

The user included Quick Dictation and recording automation in this unpublished
1.5.0 candidate: toggle-only dictation, preview with explicit Copy, and both CLI
and Apple Shortcuts. These checks extend the earlier evidence; the previous
exact-commit gate does not attest the new source.

- Focused deterministic checks passed for desired-state command idempotence,
  extra-payload rejection, CLI parsing, private mailbox bounds and file types,
  ownership transfer during relaunch, shared App Intent dispatch, schema-3
  compatibility, microphone-only dictation and explicit transcription/recovery
  with automatic recording transcription off. Vocabulary and source-preservation
  checks use only synthetic fixtures.
- Signed native Quick Dictation captured a generated test phrase through the
  built-in microphone, finalized a single microphone WAV and no system track,
  then completed real Parakeet transcription in the dedicated preview. The WAV
  decoded fully with FFmpeg. Sessions showed the finalized source, raw, cleaned,
  final and vocabulary outputs. System Default input was restored afterward.
- Signed CLI Start/Status/Stop reached the same running app. Repeating Start kept
  one active dictation; a conflicting audio start returned busy with exit 1;
  Pause returned unsupported; repeating Stop ended at idle. Responses contained
  only command IDs, phase, mode and errors.
- Packaging verified all five App Intents, three start modes, and English/Spanish
  resources. Native Shortcuts discovered all five actions and executed Start,
  Pause, Resume and Stop against one real screen recording. CLI status confirmed
  recording, paused, resumed recording and idle; Sessions showed finalization and
  both completed audio tracks. Status returned Idle both while Record was running
  and after Shortcuts launched it from a closed state.
- Native Spanish dictation controls, compact-panel labels and completed preview
  rendered correctly. Explicit Copy pasted exactly the displayed plain text into
  a new local TextEdit document, without timestamps or speaker labels. The test
  establishes the UI/copy flow, not general recognition accuracy.
- Discovery initially resolved to an older installed copy without App Intents.
  Registering the signed candidate as the local Launch Services app and reopening
  Shortcuts exposed the actions. Build-number changes alone were insufficient;
  release acceptance must test the installed application that macOS resolves.
- A working-tree full local gate passed, including TSAN, ASAN, package, metadata,
  entitlements, update signatures and checksums. Subsequent command-lifecycle
  refinements passed focused regressions; final exact-commit validation remains
  required before handoff.
- Native Apple cleanup passed on the pinned synthetic corpus. Hosted Jev remained
  incomplete, with no semantic pass. Evidence:
  `.build/jev/2026-10-04T06-18-25-620Z-62806276/workflow.json`.

No test audio, transcript, raw log, model or private preference is committed.
Physical shortcut, permission-change restart and hardware acceptance continue
as separate manual rows; passing deterministic checks does not close them. The
interface language and microphone selection were restored to Follow macOS and
System Default. The test shortcut was left with only Recording Status, so running
it does not begin capture.
