# Record 1.4.0 candidate validation

Date: 2026-09-03. Scope: Area shortcut default, preservation of existing
shortcuts, and the shoulder-mounted camcorder app icon.

## Passed locally

- Focused screenshot contract/preferences suite: 15 tests, zero failures.
- `RECORD_VERSION=1.4.0 RECORD_BUILD_NUMBER=17 ./scripts/ci/local-gate.sh`:
  319 tests, one expected external media-fixture skip, zero failures; normal,
  ThreadSanitizer, and AddressSanitizer runs passed.
- Source/privacy guards, arm64 build, package layout, nested signatures,
  entitlements, mounted DMG, test-key Sparkle appcast, and checksums passed.
- Deterministic fixtures covered a fresh profile, untouched prior storage,
  existing preferences/configuration, custom and explicit legacy bindings,
  Off, partial preferences that could collide with the new binding, repeated
  launches, and explicit Restore Defaults.
- The new SVG was rendered through `scripts/release/generate-icon.sh` and the
  generated 512-pixel app icon was visually inspected.
- A disposable harness compiled from the production shortcut contract and
  Carbon registrar registered only the new Area binding with zero failures
  while the installed Record app remained running.

## Remaining acceptance

- Computer Use could not attach to the menu-bar-only installed Record app
  (`-10005: timeoutReached`). Live Settings, installed-app upgrade, and
  screenshot capture acceptance remain unverified.
- A synthetic keypress from Computer Use did not deliver a callback to the
  disposable registrar harness. Registration success alone does not establish
  physical keyboard-to-capture acceptance. The harness was stopped afterward.
- Verify the new icon in Finder at small sizes and both appearances; perform
  the fresh-install and 1.3.2 upgrade rows in the screenshot acceptance matrix.
- The local package gate uses ad hoc signing and a disposable update key.
  These packages are QA artifacts, not notarized public release assets.
- Publication, hosted CI, notarization, public asset readback, and the real
  Sparkle upgrade path have not been performed for 1.4.0.

The full gate ran against the candidate working tree before its source commit;
its final log line names the previous HEAD. Re-run the release gate on the
exact release commit before publication, as required by the release runbook.
