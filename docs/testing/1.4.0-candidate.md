# Record 1.4.0 candidate validation

Date: 2026-09-03. Scope: Area shortcut default, preservation of existing
shortcuts, the shoulder-mounted camcorder app icon, and the matching menu-bar
camera with a blinking red recording dot.

## Passed locally

- Focused screenshot contract/preferences suite: 15 tests, zero failures.
- Focused menu controller/presentation suite: 20 tests, zero failures.
- `RECORD_VERSION=1.4.0 RECORD_BUILD_NUMBER=17 ./scripts/ci/local-gate.sh`:
  323 tests, one expected external media-fixture skip, zero failures; normal,
  ThreadSanitizer, and AddressSanitizer runs passed.
- Source/privacy guards, arm64 build, package layout, nested signatures,
  entitlements, mounted DMG, test-key Sparkle appcast, and checksums passed.
  The menu-icon gate's second packaging pass initially hit `hdiutil: verify
  failed - Resource temporarily unavailable` in the iCloud-backed checkout.
  Re-running only `scripts/ci/package-gate.sh` with the same version/build
  completed successfully, including the mounted image, appcast, and checksums.
- Deterministic fixtures covered a fresh profile, untouched prior storage,
  existing preferences/configuration, custom and explicit legacy bindings,
  Off, partial preferences that could collide with the new binding, repeated
  launches, and explicit Restore Defaults.
- The new SVG was rendered through `scripts/release/generate-icon.sh` and the
  generated 512-pixel app icon was visually inspected.
- Regeneration produced identical app-icon and embedded menu-camera hashes.
- A live native preview compiled from the production menu controller, camera
  artwork, and recording-dot view was inspected at actual 24-by-18-point size
  on light and dark backgrounds. Two observed animation phases confirmed that
  the camera remains steady while the red dot blinks. The Reduce Motion
  preview remained steady red. This was a UI simulation, not a media capture.
  The preview was stopped after inspection so no simulated recording indicator
  remained in the menu bar.
- Tests cover the lower-right dot bounds/color, click pass-through, dot-only
  animation without a restart on repeated updates, Reduce Motion changes,
  screen/audio/pause/resume/stop states, and screenshot-feedback restoration.
- The placement inset over the camera body's lower right passed 17 menu
  controller tests and `scripts/ci/validate.sh` (323 tests, one expected
  fixture skip, zero failures).
  The production view was checked again in the native light/dark preview.
- A disposable harness compiled from the production shortcut contract and
  Carbon registrar registered only the new Area binding with zero failures
  while the installed Record app remained running.

## Remaining acceptance

- Computer Use could not attach to the menu-bar-only installed Record app
  (`-10005: timeoutReached`). Live Settings, installed-app upgrade, and
  screenshot capture acceptance remain unverified.
- A synthetic keypress from Computer Use did not deliver a callback to the
  disposable registrar harness. Registration success alone does not establish
  physical keyboard-to-capture acceptance. The harness was stopped afterward.
- Verify the new icon in Finder at small sizes and both appearances; perform
  the fresh-install and 1.3.2 upgrade rows in the screenshot acceptance matrix.
- The local package gate uses ad hoc signing and a disposable update key.
  These packages are QA artifacts, not notarized public release assets.
- Publication, hosted CI, notarization, public asset readback, and the real
  Sparkle upgrade path have not been performed for 1.4.0.

The gates ran against the candidate working tree before its source commit;
the original gate's final log line names the previous HEAD. The menu-icon
follow-up completed through the packaging retry described above. Re-run the
release gate on the exact release commit before publication, as required by
the release runbook.
