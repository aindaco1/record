# Record 1.4.1

Record 1.4.1 fixes capture scope, source loss, region selection on secondary
displays, and stopping during screen-recording Resume.

- Application recordings and screenshots preserve the application selected in
  Apple's picker, even when macOS describes that selection as display-bound.
  Unrelated application windows are no longer included by that classification.
- Application and window recordings stop with recoverable media when the
  selected application exits, including when ScreenCaptureKit continues sending
  audio callbacks. The additional process-lifetime check supports system-picker
  selections on macOS 15.2 and later.
- Area-selection overlays appear on the correct secondary display, including
  displays positioned to the left or above the main display. The same fix
  applies to area screenshots and custom-region recordings.
- Start and Resume wait for the first processed sample from every requested
  media track. A pending Stop can then finalize the new segment instead of
  failing because an audio or video track is still empty. Missing tracks time
  out within five seconds while preserving existing recovery media.

On macOS 15.0–15.1, ambiguous display-bound picker selections now stop before
capture because those versions cannot expose the selection's scope safely.
**Main Display** and custom-region recording remain available. Update macOS to
15.2 or later for the complete picker inspection and source-lifetime behavior.

The signed local candidate was exercised with synthetic sources on standard and
Retina virtual displays, including source termination, window destruction,
display removal, repeated pause/resume, stop during rotation, and forced-quit
recovery. The full local gate passed 342 tests with one expected external-fixture
skip, plus sanitizers and package checks. See the
[acceptance report](../testing/source-and-recovery-2026-09-07.md) for the exact
coverage and remaining desktop-Space and permission-classification checks.

Record remains local-only. Final video, microphone audio, and system audio stay
in separate files, and raw capture media is retained until complete export
validation succeeds.
