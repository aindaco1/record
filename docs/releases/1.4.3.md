# Record 1.4.3

Record 1.4.3 fixes transcription failing when the Save to folder changes while
a finished recording is still being processed.

Each queued job now keeps the original folder's approved access through speech
processing and transcript output. A failed job retains that access for its
available retry. Choosing another folder continues to apply to future captures.
The audio files remain separate and unchanged.

The failure was reproduced in the signed 1.4.2 app on macOS 27: restoring the
Save to preference during model preparation caused a file-permission error.
Re-selecting the original folder recovered the transcript without re-recording.
Regression checks cover the retained access and its release after retry state
is cleared or replaced. Native acceptance and release evidence are tracked in
the [macOS 27 audit](https://github.com/aindaco1/record/issues/45).

This release retains the reviewed FluidAudio 0.15.7 runtime and the Xcode 27
build and packaging coverage added in 1.4.2. The app remains sandboxed and its
main process has no network entitlement.
